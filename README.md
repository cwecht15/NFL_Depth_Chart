# Depth Chart Editor — GitHub Pages site

A static depth-chart editor hosted on GitHub Pages. Reads a JSON snapshot of
the `2026 Depth Chart` Google Sheet that a scheduled GitHub Action commits
to this repo. Edits happen entirely in the browser (persisted to
`localStorage`) and can be downloaded as CSV / JSON. **Nothing in this app
writes back to the Google Sheet.**

Looks and feels like the user's existing `NFL_Draft_Value_Chart` — dark
navy + coral accent, compact tables, sticky headers, badge UI.

## One-time setup

1. **Create a GitHub repo** and push this folder.

   From this folder:
   ```bash
   git init
   git add .
   git commit -m "Initial commit"
   gh repo create depth-chart-editor --public --source=. --push
   ```

2. **Add the service-account key as a repo secret.**

   In Repo → Settings → Secrets and variables → Actions → New secret:
   - **Name**: `FP_DATA_KEY_JSON`
   - **Value**: paste the full contents of
     `C:/Users/cwech/Documents/Football/Keys/fp-data-357113-a6174bb87054.json`

3. **Enable GitHub Pages.**

   Repo → Settings → Pages:
   - **Source**: `Deploy from a branch`
   - **Branch**: `main`, folder `/docs`

4. **Seed the first snapshot.**

   Repo → Actions → "Pull DepthChart Snapshot" → "Run workflow" (on `main`).
   In about a minute the workflow commits `docs/data/snapshot.json` and Pages
   redeploys.

5. **(Optional) Turn on auth.**

   Create a Google OAuth Client ID:
   - GCP Console → APIs & Services → Credentials → Create Credentials → OAuth Client ID
   - Type: Web application
   - Authorized JavaScript origins: `https://<your-github-username>.github.io`
   - Copy the resulting client ID

   Then in the repo, copy `docs/auth.config.json.example` to
   `docs/auth.config.json` and fill in the client ID and editor allowlist:
   ```json
   {
     "client_id": "1234-abc.apps.googleusercontent.com",
     "allowlist": ["alice@gmail.com", "bob@gmail.com"]
   }
   ```
   Commit and push.

   Without `auth.config.json`, the site loads in dev mode (no sign-in
   gate).

That's it. The cron in `.github/workflows/snapshot.yml` refreshes the snapshot
every 15 minutes by default; adjust the cron expression if you want a
different cadence. Manual triggers are also available from the Actions tab.

## Local development

```bash
# 1. Generate a snapshot using your local service-account key:
cd tools && pip install -r requirements.txt && cd ..
python tools/pull_snapshot.py

# 2. Serve the docs/ folder with any static server:
cd docs && python -m http.server 8000
# -> http://localhost:8000
```

If `auth.config.json` is absent locally, the site skips the auth gate.

## What it does

- Loads `DepthCharts`, `Rosters`, `Options` from the committed snapshot.
- Sidebar-free top-bar layout: team selector + category tabs + tables grouped
  by `depthPosition`, sorted by `depthOrder`.
- Editable cells for the manual columns (`eliasId`, `gsisId`, `jersey`,
  `team`, `status`, `depthPosition`, injury fields, edge/FA/trade flags,
  `displayName`). Read-only formula columns are visible but greyed out.
- "Add a player" form with `Rosters`-backed autocomplete and ID auto-fill.
- Edits accumulate in `localStorage` and survive reloads; "Discard edits"
  clears them.
- Two export buttons: full edited CSV, and diff/log JSON.
- Placeholder IDs (`ROOKIE###`) are visibly flagged so they're easy to spot.

## What it does NOT do

- Write back to the Google Sheet (by design).
- Realtime collaborative editing — `localStorage` is per-browser. Two editors
  can each download their own diff and a human reconciles.
- Bypass the snapshot cadence — fresher data requires running the workflow
  manually or moving to the "serverless proxy" variant.

## Verifying the no-write guarantee

The bundled service-account scopes are read-only:
```
spreadsheets.readonly
drive.readonly
```

And the static frontend has no service-account credentials at all — the
key never reaches the browser, only the GitHub Action.

```bash
grep -RIn "batchUpdate\|append_row\|setValues\|update_cells" tools/ docs/  # -> 0 matches
```
