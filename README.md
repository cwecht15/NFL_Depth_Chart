# Depth Chart Editor — GitHub Pages site

A static depth-chart editor hosted on GitHub Pages. A scheduled GitHub
Action reads the live `2026 Depth Chart` Google Sheet via the `fp-data`
service account and commits `docs/data/snapshot.json` to this repo;
GitHub Pages serves the static frontend from `docs/`. Edits happen
entirely in the browser (`localStorage`) and can be exported as CSV/JSON.
**Nothing here writes back to the Google Sheet.**

```
pages-site/
├── docs/                         <- GitHub Pages serves from here
│   ├── index.html
│   ├── app.js
│   ├── styles.css
│   ├── auth.config.json.example  -> copy to auth.config.json
│   └── data/snapshot.json        <- generated by the workflow
├── tools/
│   ├── pull_snapshot.py
│   └── requirements.txt
├── .github/workflows/snapshot.yml
└── .gitignore
```

The repo is **public** so GitHub Pages works on the free plan and
collaborators can fork / file PRs without needing repo invites. The
snapshot JSON is therefore publicly readable too — if that matters,
move to GitHub Pro for private + Pages, or proxy through a Cloudflare
Worker.

## One-time setup

### 1. Add the service-account key as a repo secret

Already done. Verify with:
```bash
gh secret list -R cwecht15/NFL_Depth_Chart
# -> FP_DATA_KEY_JSON  <date>
```

If you need to refresh it:
```bash
gh secret set FP_DATA_KEY_JSON -R cwecht15/NFL_Depth_Chart \
  < "C:/Users/cwech/Documents/Football/Keys/fp-data-357113-a6174bb87054.json"
```

### 2. Enable GitHub Pages

Repo → **Settings → Pages**:
- **Source**: `Deploy from a branch`
- **Branch**: `main`, folder `/docs`

(Or via API: `gh api -X POST repos/cwecht15/NFL_Depth_Chart/pages -f "source[branch]=main" -f "source[path]=/docs"`.)

Pages will publish to `https://cwecht15.github.io/NFL_Depth_Chart/`.

### 3. Seed the first snapshot

Repo → **Actions** → "Pull DepthChart Snapshot" → **Run workflow** on `main`,
or:
```bash
gh workflow run "Pull DepthChart Snapshot" -R cwecht15/NFL_Depth_Chart
```

The workflow commits `docs/data/snapshot.json`. Pages redeploys within a
minute. The cron then refreshes every 10 minutes.

### 4. (Optional) Turn on Google sign-in

1. GCP Console → **Credentials** → **Create credentials** → **OAuth Client ID**
   → Web application.
2. Authorized JavaScript origins: `https://cwecht15.github.io`
3. Copy the client ID.
4. Locally:
   ```bash
   cp docs/auth.config.json.example docs/auth.config.json
   # Fill in client_id and the editor allowlist.
   git add docs/auth.config.json
   git commit -m "Enable Google sign-in"
   git push
   ```

Without `auth.config.json`, the site loads with no sign-in gate (anyone
with the URL sees the editor UI — but cannot write to the sheet anyway).

## Local development

```bash
# 1. Install Python deps
pip install -r tools/requirements.txt

# 2. Pull a local snapshot (uses FP_DATA_KEY_PATH; defaults to the
#    fp-data key under C:/Users/cwech/Documents/Football/Keys/)
python tools/pull_snapshot.py
# -> writes docs/data/snapshot.json

# 3. Serve docs/ with any static server
cd docs && python -m http.server 8000
# -> http://localhost:8000
```

## What it does

- Renders depth charts from the live snapshot, grouped by team /
  category (OFF / DEF / ST / IR / SUS / PS) / depth position.
- Inline cell editing for the manual columns (`eliasId`, `gsisId`,
  `jersey`, `team`, `status`, `depthPosition`, injury fields, edge/FA/
  trade flags, `displayName`). Formula columns are read-only.
- "Add a player" form with `Rosters`-backed autocomplete; selecting a
  name auto-fills `eliasId` and `gsisId`.
- Edits persist to `localStorage`; "Discard edits" clears them.
- Two export buttons: full edited CSV, diff/log JSON.
- Placeholder IDs (`ROOKIE###`) are visibly flagged.

## What it does NOT do

- Write back to the Google Sheet by design. The fp-data service-account
  scopes are read-only (`spreadsheets.readonly`, `drive.readonly`). The
  key never reaches the browser — only the GitHub Action sees it.
- Realtime collaborative editing. Edits are per-browser; two editors
  download their own diffs and a human reconciles.
